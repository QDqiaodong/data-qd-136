# 库存成本归属与追补发票工作台 · Inventory cost attribution v1

面向账务数据整理人员，把一份**收货 / 领用 / 退回 / 采购总成本修订（追补发票）**的事件快照，
转换为带来源身份、可逐步追溯的库存估值、部门费用与复式分录，并输出逐币种全科目试算表与
勾稽核对。工作台只做本地精确核算：全部使用整数运算，**没有任何浮点**；仅依赖 Python
标准库，无网络服务。

试算核验（`analyze(data)`、原 `journal-check --source ... --output ...` 命令与 v1 报告）、
开放项、期间结转链与折算工作台的行为全部保持不变；本功能是独立的 `inventory-cost`
子命令和独立的 Python 包 `journal_check.inventory_cost`。它**不读写开放项数据库与结转链
存储、不做开放项配对、不做期间结转、不做币种换算**。

---

## 1. 请求文件与标识规则

`--source` 读取一份受现有 **8 MB 严格 JSON** 约束的请求：重复 JSON 键、`NaN`/`Infinity`、
未定义字段一律拒绝；其源字节 SHA256 随结果报告保留。顶层对象**恰为**三个字段：
`accounts`、`stocks`、`events`。

### 1.1 accounts

沿用 v1 的科目定义校验：1..1000 个唯一 `id`，每个恰有 `id` 与 `normal`
（`debit`/`credit`）；重复科目或非法 normal 失败。请求至少定义一个科目。

### 1.2 stocks（至多 1000 项）

每项恰为 `sku`、`currency`、`inventory_account`、`payable_account`：

- 标识沿用现有标识符规则（非空、去首尾空白后等于自身、≤128 字符、无控制字符）；
- `(sku, currency)` 全局唯一，标识一个**库存池**；
- 两个科目都必须在 `accounts` 中定义；
- 全部库存科目构成的集合与全部应付科目构成的集合**必须不相交**；任一集合内部允许多个
  库存池共用同一科目（同币种多个 SKU 可共用一个库存或应付科目）。

### 1.3 events（至多 5000 项）

所有事件恰有公共字段 `id`、`seq`、`type` 以及下列类型字段；`id` 全局唯一，
`seq` 为 `0..10**9` 的唯一整数。**处理顺序严格按 `seq` 升序，与输入数组排列无关**。
数量为 `1..10**12` 整数，金额为 `0..10**18` 整数；布尔、浮点、未知字段、非法引用一律
拒绝，任一非法事件都**拒绝整个请求**。

| 类型 | 类型字段 | 语义 |
| --- | --- | --- |
| `receipt` | `sku, currency, quantity, total_cost` | 建立一个收货批，单位序号为 `[0, quantity)` |
| `issue` | `sku, currency, quantity, expense_account` | 从该库存池领用；费用科目不得是任何 stocks 使用的库存/应付科目，且必须已定义 |
| `return` | `issue, quantity` | 只能引用 `seq` 更早的领用；累计退回不得超过该次领用量 |
| `reprice` | `receipt, total_cost` | 只能引用更早收货；新值**替代**该批当前总成本，不是增量 |

顺序性非法（无库存可领、跨池/未知池引用、未来引用、超退、超领）在按 `seq` 回放时判定，
同样整次失败。`return` 必须引用一个 `issue`，`reprice` 必须引用一个 `receipt`，
交叉引用即非法。

## 2. 带来源身份的实物流转

每个收货批拥有自己的单位序号空间 `[0, Q)`。一切实物归属都表示为**原收货单位序号的半开
区间** `[start, end)`，并带 `receipt` 来源 id；单位一旦被领用，其来源身份永不丢失，退回时
恢复到**原收货批的原序号**。所有操作只作用于区间端点，时间与空间均不随 `Q` 或成本
`C` 增长，天然支持 `Q = 10**12`。

### 2.1 领用（FIFO）

领用总按 `(原 receipt.seq, 单位序号)` 升序取可用单位：先在最老收货批内取最低序号，
不足再跨到下一批；可用数量不足即失败。一次领用可能产生多个来源区间（跨批领用）。

### 2.2 退回（倒序撤销）

退回依次撤销被引用 issue **尚未退回**的单位，按其原领用分配顺序**倒序**取：先撤销该次
领用最后拿到的单位。退回单位恢复到原收货批、原序号，并在恢复后**仍按原收货年龄参与
FIFO**——不会被排到新批之后，也不会产生新的序号。

验收：同批 `[0,5)` 先领用 3（得 `[0,3)`），再退回该 issue 的 2，倒序撤销单位 2、单位 1，
退回区间必须为 `[1,3)`；下一次领用 2 必须重新取走 `[1,3)`。另验收跨批领用、重复部分
退回与超退拒绝。

### 2.3 输出的区间证据

报告逐事件给出收货批 / 半开单位区间与数量，并在结尾给出：

- 每个收货批的**最终可用区间**与可用数量；
- 每个 issue 的**未退回区间**与未退回数量。

全部归属区间之间不得重叠、丢失或重复：每个收货批的“可用区间 ∪ 各 issue 未退回区间”
恰好无重叠地覆盖 `[0, 数量)`。引擎在每次回放后对该不变量做断言式核对。

## 3. 整批前缀成本定义（精确整数）

收货批总成本 `C`、收货量 `Q` 下，原单位区间 `[a, b)` 的成本由批前缀函数定义：

```
cost([a, b)) = floor(C * b / Q) - floor(C * a / Q)
```

多个区间的成本为各区间前缀差之和。规则硬性要求：

- **禁止浮点**；
- 禁止按平均单价再舍入；
- 禁止按数量逐单位展开（实现只在区间端点做整数乘除，复杂度正比于区间片段数，
  与 `Q`、`C` 无关）。

验收 `Q = 3, C = 5` 的三个单单位成本分别为 `1、2、2`；改为 `C = 7` 后为 `2、2、3`
——不能平均分配成三笔相同差额。降价（如 `C = 4` 得 `1、1、2`）与改成零（全部为 0）
同样按前缀定义处理。整批区间 `[0, Q)` 的前缀成本恒等于 `C`。

### 3.1 reprice 不改变实物分配

`reprice` 不移动任何单位，只按该批**当前所有者分区**分别重估：

- 仍在库存的单位 → 库存；
- 每次领用**仍持有**（未退回）的单位 → 对应 issue 的费用科目；
- 已退回单位属于库存；已被后续领用的单位属于后续 issue。

每次 reprice 按当前所有者（库存或 issue）逐区间列明旧成本、新成本与有符号差额，
**各区间差额之和必须等于整批总成本变化** `新 C − 旧 C`。

### 3.2 实物归属决定 reprice 科目

若某单位先被 A 领用、退回、再被 B 领走，则追补差额只能计入当前持有者 B 的费用，
不能再记 A 或库存；历史领用/退回分录保持当时金额，绝不追改旧事件分录。

联合验收：收货 `Q=3/C=5`，A 领走 `[0,2)`，退回 `[1,2)`，B 再领走 `[1,2)`，把 C 改为 7：
追补分录为**借 A 费用 1、借库存 1、贷应付 2，B 无调整**；最终 A 费用 2、B 费用 2、
库存 3、应付贷 7，实物上 A、B 与库存各持一单位。随后把 C 改为 4 并再退回 A 的一单位：
按新成本冲回 A 费用，最终 A 费用 0、B 费用 1、库存 3、应付贷 4，实物库存为 2 单位。

## 4. 复式分录与账表勾稽

### 4.1 四类事件的分录方向

| 事件 | 分录 |
| --- | --- |
| `receipt` | 借库存科目，贷该批应付科目，金额为收货总成本 |
| `issue` | 借该 issue 自己的费用科目，贷对应库存科目，金额按所取各区间当前前缀成本 |
| `return` | 按**退回当时**该批当前成本，借库存科目，贷原 issue 费用科目 |
| `reprice`（正差额） | 借当前所有者对应库存/费用科目，贷该批应付 |
| `reprice`（负差额） | 方向反转：借该批应付，贷当前所有者科目 |

### 4.2 逐归属成行、禁止轧差

每个非零成本归属单独形成一条**带来源**的归属记录，并各自生成一对平衡分录行，行内带
`attribution` 序号回指归属；**不能先跨 issue 净额相抵**，同一批向不同费用科目的追补必须
分别调整。零成本流转（零成本收货/领用/退回、零差额重估）保留实物证据与重估清单，但
**不生成零金额分录行**。每个有金额事件的借方合计等于贷方合计。

生成金额允许超过 v1 输入分录的 `10**12` 上限（库存成本可达 `10**18`）；旧
`parse_journal` 的金额规则不被放宽，两个工作台互不喂数。

### 4.3 试算表与勾稽

试算表复用现有 `ledger.balance` 语义，按币种输出**全部已定义科目（含零科目）**的
借方累计、贷方累计、净借/净贷及按 normal 方向的有符号 `normal_balance`；请求中出现的
每个币种即使没有任何非零分录也会列出全部科目。报告内 `reconciliations` 独立核对：

1. 每批当前总成本 = 库存估值 + 各 issue 未退回成本；
2. 试算表某库存科目余额 = 同币种映射到该科目的各批估值合计；
3. 各费用科目余额 = 其各 issue 未退回领用成本合计；
4. 各应付科目贷方余额 = 映射到该科目的各批当前总成本合计。

任一核对不符都会以断言失败中止，而不是用“总借 = 总贷”代替这些勾稽。全部历史分录累计
即可还原最终费用与库存余额。

## 5. 报告结构

报告为可独立读取的排序键 JSON，含：

| 字段 | 内容 |
| --- | --- |
| `schema_version` | 报告版本，当前为 1 |
| `source_sha256` | 源文件字节 SHA256（Python 接口未给摘要时为 `null`） |
| `events` | 规范 `seq` 排序的完整事件轨迹（回显校验后的事件字段） |
| `physical_trace` | 逐事件的收货批 / 半开单位区间、数量等实物来源证据 |
| `cost_attributions` | 逐区间成本归属（事件、所有者、来源批与区间、成本基础、金额、有符号金额） |
| `entries` | 逐事件复式分录；每条分录行带 `attribution` 回指归属，零金额事件保留空行列表 |
| `revaluations` | 每次 reprice 的旧/新总成本、总变化与按当前所有者逐区间的旧成本、新成本、差额、科目 |
| `final_positions` | 最终每收货批可用区间/估值与每 issue 未退回区间/成本 |
| `trial_balance` | 逐币种全科目试算表（复用现有 ledger 余额语义，含全部零科目） |
| `reconciliations` | 第 4.3 节四类勾稽明细与总判定 `all_balanced` |
| `statistics` | 事件/库存池/各类型计数、归属数、分录行数、币种清单 |

## 6. 命令行

```sh
journal-check inventory-cost --source request.json --output report.json
```

- 沿用 8 MB 严格 JSON 读取与共享的原子报告发布：输出拒绝符号链接，失败时保留旧报告；
- 输出路径必须避开源文件及其解析后同路径（同路径拒绝）；
- 输入/计算/I/O 失败打印原因到 stderr 并以 **退出码 2** 结束，无部分成功报告；
- 成功时报告同时原子写入 `--output` 并打印到 stdout，退出 0。

## 7. Python 接口（可被测试直接调用）

```python
from journal_check.inventory_cost import inventory_cost, run_file, publish
from journal_check.inventory_cost.errors import (
    InventoryCostError, InventoryValidationError,
)
from journal_check.inventory_cost.costing import prefix_cost, segments_cost
from journal_check.inventory_cost.intervals import (
    take_prefix, take_tail, take_tail_labeled, restore,
)

# data 为已解析的严格 JSON 对象；source_sha256 可选
report = inventory_cost(data, source_sha256='<hex digest>')

# 或交给工作台完成严格 8 MB 读取（自动附带源字节 SHA256）
report = run_file('request.json')
publish(report, 'report.json')   # 走共享的安全原子发布
```

纯算法拆分：校验在 `journal_check.inventory_cost.validation`，区间代数在
`intervals`，精确前缀成本在 `costing`，回放与账务在 `engine`，均不接触文件系统
（`run_file`/`publish` 除外）。

## 8. 异常约定

所有工作台异常都是 `ValueError` 的子类，CLI 统一映射为退出码 2 且不触碰旧报告：

| 异常 | 触发场景 |
| --- | --- |
| `InventoryValidationError` | 顶层/事件结构、标识符、字段、数值边界、引用、科目族规则或顺序性实物约束非法 |
| `InventoryCostError` | 库存成本工作台异常基类（上述异常的父类） |

本工作台没有“待处理”业务态：任何非法输入都是整次失败；合法但全零成本的流转是退出 0
的正常结果。

样例数据均为原创虚构（见 `fixtures/SOURCES.md`），不代表真实主体或真实账务。
