# 报价证据驱动的多币种分录折算 · Quote-evidence translation v1

面向账务数据整理人员，把一份**原币分录快照**按逐日报价证据折算为**单一展示币种**的试算表，
并识别因报价不可采信而**暂不能入账**的分录。工作台只做本地精确核算：所有倍率与金额均为
精确有理数，全程不使用浮点；仅依赖 Python 标准库（`fractions`、`datetime`、`json` 等），无网络服务。

试算核验（`analyze(data)`、原 `journal-check --source ... --output ...` 命令与 v1 报告）、
开放项工作台与期间结转链工作台的行为全部保持不变；本功能是独立的 `translate` 子命令和独立的
Python 包 `journal_check.translate`。它**不消费开放项与结转链的任何存储、不核销开放项、不结转期间**。

---

## 1. 请求文件与标识规则

`--source` 读取一份受现有 **8 MB 严格 JSON** 约束的请求：重复 JSON 键、`NaN`/`Infinity`、
未定义字段一律拒绝；其源字节 SHA256 随结果报告保留。顶层对象**恰为**五个字段：

| 字段 | 约束 |
| --- | --- |
| `journal` | 沿用 v1 的 `accounts` / `entries` 结构，先通过原 `parse_journal` 的全部校验 |
| `target` | 目标展示币种标识，沿用 v1 标识符规则 |
| `rounding_account` | 折算差额入账科目，**必须是 journal 中已定义的科目** |
| `entry_dates` | 恰覆盖全部分录、无重复的 `{entry, date}` 数组 |
| `quotes` | 报价数组，至多 **2000** 项 |

- journal 的原金额（`1..10**12` 整数、禁止布尔/浮点）、借贷平衡、未知科目/重复分录失败、
  重复科目行合法等规则**完全不变**。折算产生的零金额不会被塞回原 journal 校验器。
- `entry_dates` 每项恰为 `entry` 与 `date`：`entry` 必须引用存在的分录，每个分录恰出现一次；
  `date` 必须是**真实公历** `YYYY-MM-DD`（`2026-02-29`、`2026-13-40` 等均拒绝）。
- 全部出现币种（journal 币种、`target` 与报价中出现的桥接币种）至多 **60** 种；
  分录日期至多 **366** 种。

### 报价对象

每项报价**恰为** `id`、`base`、`quote`、`numerator`、`denominator`、`valid_from`、`valid_to`：

| 字段 | 约束 |
| --- | --- |
| `id` | 标识符，全请求唯一 |
| `base` / `quote` | 两个**不同**的币种标识 |
| `numerator` / `denominator` | `1..10**9` 的整数，**禁止布尔** |
| `valid_from` / `valid_to` | 真实公历日期，区间**左闭右开** `[valid_from, valid_to)` 且非空 |

报价语义：**1 个 `base` 最小货币单位可兑换 `numerator/denominator` 个 `quote` 最小货币单位**；
不再推测任何币种精度。同一币种对可以存在多条独立（含平行）报价。

任何字段或引用非法都是**整次失败**（退出码 2），不是业务待处理。

## 2. 逐日期报价证据解析

解析**按分录日期逐日独立进行**：只采用当天有效的报价（左闭右开区间），报价可沿其正向或倒数
方向换算。当天有效报价构成一张无向多重图，每个连通分量按生成树遍历，且所有输出均按 id 规范
排序——**倍率与状态不随输入排列变化**。

### 2.1 分量可采信判定（禁止浮点容差、禁止只选最短路）

一个连通分量**可采信，当且仅当其中任意闭合报价路径的倍率乘积严格等于 1**。实现上等价于：
以生成树推出各节点相对倍率，再用每条非树边与树倍率逐一精确比对。因此：

- 不枚举全部路径，也不按最小货币单位循环，复杂度对当天有效边数为线性；
- 不允许用“选最短路”或“优先直接报价”掩盖矛盾——只要存在一条乘积 ≠ 1 的闭合路径，整个分量不可采信。

### 2.2 每个非目标原币的当天状态

| 状态 | 含义 | 证据 |
| --- | --- | --- |
| `ready` | 分量一致且存在到 `target` 的路径 | 约分后的精确倍率 `{numerator, denominator}` 与一条可核算的报价 ID/正反方向路径 |
| `inconsistent` | 所在分量矛盾（**优先于**不可达） | 一条由当天有效报价组成、乘积 ≠ 1 的闭合见证（连续闭环步骤与精确乘积） |
| `missing` | 分量一致但无路到达 `target` | 该分量的可达币种集合 |

原币等于 `target` 时**恒为 `ready`、倍率 `1/1`、路径为空且不依赖任何报价**，即使提到该币种的
报价自相矛盾。证据路径不要求唯一，但必须由当天真实有效的报价组成，步骤的方向（`forward`/
`reverse`）与逐段乘积都可被独立复核。

### 2.3 验收图

- 报价 `A→B=2`、`B→T=3`、`A→T=7`：树推 `A→T` 应为 6，直接报价为 7，故 **A、B 当天均不可信**
  （`inconsistent`），报告给出乘积 `7/6`（或其倒数，视见证方向而定）的闭合见证；
- 去掉直接报价后，A 沿 `A→B→T` 得到**精确倍率 6**；
- 倒数方向报价（如 `T→A=6` 推出 `A→T=1/6`）、互相一致的平行报价、以及与健康分量**互不相连**的
  矛盾分量，均分别验收：互不相连的矛盾不会污染健康分量。

## 3. 折算账务与逐行证据追溯

仅对 `ready` 分录执行折算；所有计算使用 `fractions.Fraction`，允许中间金额超过 journal 输入的
`10**12` 上限。

### 3.1 逐行精确折算与四舍六入五成双

对 ready 分录的**每条原行分别**计算精确有理金额 `原币整数 × 倍率`，再按
**四舍六入五成双（round-half-to-even / banker's rounding）** 舍入到目标最小货币单位，整数结果：

- **重复科目行不得提前合并**——合并会改变舍入结果（例如两行各 1、倍率 1/2，逐行舍入各为 0，
  合并后金额 2 再舍入为 1，结果不同）；
- 原行无论舍入为 0 还是重复科目行，都保留一条 `(entry, line 零基序号)` 追溯，含原币金额、
  倍率证据（状态、精确倍率、报价路径）、精确分数 `exact_amount` 与舍入整数 `rounded_amount`；
- 舍入为 0 的原行仍在逐行追溯中，但**不进入试算汇总**。

### 3.2 折算差额与追加行

每条分录用“舍入后借方和 − 舍入后贷方和”得差额 `d`：

- `d > 0`：向 `rounding_account` **追加贷方 d**；
- `d < 0`：向 `rounding_account` **追加借方 -d**；
- `d = 0`：不追加。

追加行单独标记 `kind: "rounding"`（原行为 `"original"`），带所属分录与行号，**绝不与原行合并**
以掩盖来源。验收：两条借方各 1、一条贷方 2，倍率 `1/2` 时分别舍入为 `0、0、1`，须追加**借方 1**；
倍率 `3/2` 时为 `2、2、3`（1.5 五成双到偶数 2），须追加**贷方 1**，且原始行逐行追溯仍在。

### 3.3 目标试算表与平衡核验

试算汇总只含折算后的非零原行与追加行：

- 输出**全部已定义科目（含零额科目）**的借方累计、贷方累计、净借/净贷及按 `normal` 方向的
  有符号 `normal_balance`（实际借贷方向决定符号，反常余额如实反映）；
- 逐分录核验借 = 贷（含追加行），整体试算总借 = 总贷、净借 = 净贷。

## 4. 报价状态决定入账资格（业务联动）

- **只有当天状态 `ready` 的分录才进入目标账**；`inconsistent` / `missing` 分录**整条**进入
  待处理列表 `pending_entries` 并携带证据（矛盾闭合见证或可达币种集合），其任何原行金额与
  差额都**不能泄漏**到试算汇总；
- 同一份完整请求中，某报价的有效区间边界或倍率变化，必须**重新决定受影响日期分录的入账资格**，
  再重算其逐行舍入与差额——不是只替换报告里的报价状态文字；
- **有待处理项是可成功生成报告的业务结果，退出码 0**，绝不能把待处理金额当作零元成功。

### 联合验收（两日期）

T 币分录与 A 币分录各位于两个日期：第一天 `A-B-T` 一致（A 倍率 6，全部入账）；第二天一条新生效的
`A→T` 矛盾报价使当天 A 分录 `inconsistent` 待处理，而 T 币分录不受影响、照常入账。修正该报价后：

- 只改变第二天 A 分录的资格、逐行金额与差额；
- 第一天的报价解析与全部 T 币分录结果保持不变；
- 全部来源分录**恰一次**出现在“入账”或“待处理”中，二者不重不漏。

另覆盖：报价在边界失效使分量变成 `missing`（含整体无报价的孤立币种），以及互不相连的矛盾分量
不污染健康分录。

## 5. 报告结构

报告为可独立读取的排序键 JSON，含：

| 字段 | 内容 |
| --- | --- |
| `schema_version` | 报告版本，当前为 1 |
| `source_sha256` | 源文件字节 SHA256（Python 接口未给摘要时为 `null`） |
| `target_currency` / `rounding_account` | 目标币种与差额科目回显 |
| `quote_resolution` | 逐日期（规范日期序）的有效报价 id 与各币种状态、倍率、路径/见证/可达集合 |
| `entry_qualification` | **完整分录资格清单**，按分录 id 排序，含日期、原币、状态（ready 附倍率） |
| `line_trace` | 入账分录的**逐原行追溯**，按 `(entry, line)` 排序，含原币金额、倍率证据、精确分数与舍入整数 |
| `rounding_lines` | 单独标记的折算差额追加行 |
| `entry_balances` | 逐分录借/贷核验（`balanced: true`） |
| `pending_entries` | 待处理分录及原因证据；待处理金额不计入试算表 |
| `trial_balance` | 单一目标币种试算表：全部科目（含零）、借贷累计、净借贷、normal 余额与合计 |
| `statistics` | 分录总数、入账/待处理数，以及按原币、按状态分别统计的分录数 |

---

## 6. 命令行

```sh
journal-check translate --source request.json --output report.json
```

- 沿用 8 MB 严格 JSON 读取与共享的原子报告发布：输出拒绝符号链接，失败时保留旧报告；
- 输出路径必须避开源文件及其解析后同路径（同路径拒绝）；
- 结构/校验/计算/I/O 失败打印原因到 stderr 并以 **退出码 2** 结束；有待处理分录仍**退出 0**；
- 成功时报告同时原子写入 `--output` 并打印到 stdout。

## 7. Python 接口（可被测试直接调用）

```python
from journal_check.translate import translate, run_file, publish
from journal_check.translate.errors import (
    TranslateError, TranslationValidationError,
)
from journal_check.translate.rates import resolve_day
from journal_check.translate.engine import round_half_even

# data 为已解析的严格 JSON 对象；source_sha256 可选
report = translate(data, source_sha256='<hex digest>')

# 或直接交给工作台完成严格 8 MB 读取（自动附带源字节 SHA256）
report = run_file('request.json')
publish(report, 'report.json')   # 走共享的安全原子发布
```

纯报价图解析（不接触文件系统）在 `journal_check.translate.rates`，
校验、逐行折算与试算汇总在 `journal_check.translate.engine`。

## 8. 异常约定

所有工作台异常都是 `ValueError` 的子类，CLI 统一映射为退出码 2 且不触碰旧报告：

| 异常 | 触发场景 |
| --- | --- |
| `TranslationValidationError` | 顶层/报价/日期结构、标识符、引用、区间或数值非法；journal 未通过原 `parse_journal` 校验时抛其原有 `ValueError` |
| `TranslateError` | 折算工作台异常基类（上述异常的父类） |

待处理（`inconsistent`/`missing`）**不是异常**：它是退出 0 的正常业务结果。

样例数据均为原创虚构（见 `fixtures/SOURCES.md`），不代表真实主体或真实账务。
